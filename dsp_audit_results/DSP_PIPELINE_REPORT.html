RadarStream DSP and sparse XYZ investigation

November 20, 2026 • IWR6843ISK / DCA1000EVM • Current local source plus five November19 evening captures

Confirmed software blind spot: the offline detector's fixed edge exclusion made the 1.405m range cell ineligible. The range plot could show that return while the detector never attempted its XYZ. A counted, truncated edge window restores that opportunity without lowering SNR or adding arbitrary noise points.

The live app and the offline script are different paths. The live app produces feature heatmaps, with stationary-clutter suppression on by default and legacy four-channel angle selections. The offline script already uses the joint physical ISK geometry and produces candidate XYZ. No new radar-processing system was needed.

3. Antenna mapping assessment

The decoded order is TX0/RX0..3, TX1/RX0..3, TX2/RX0..3. In half design-wavelength units, the assumed ISK virtual rows are TX0:(0..3,0), TX1:(2..5,1), TX2:(4..7,0). This agrees with TI's TX/RX geometry description. All12 are not one horizontal ULA. See the complete mapping.

For that geometry, the live azimuth selection (7,4,3,0) occupies (5,1),(2,1),(3,0),(0,0): it changes both height and horizontal position. The elevation selection (7,6,11,10) occupies (5,1),(4,1),(7,0),(6,0): it is not a vertical ULA either. gen_steering_vec assumes an ordered half-wavelength 1D ULA, so these selections are mathematically inconsistent with that model. AppConfig checks index bounds and lengths, not physical geometry.

The offline isk_positions and steering_grid already use the correct nominal two-row model. Its TDM compensation uses each TX slot's chirp time. Channel corrections remain identity without a matching calibration file; mount roll defaults zero; phase and velocity signs are explicit unvalidated conventions. Synthetic direction/TDM tests pass, but software consistency is not independent certification of physical RX labels, native DLL packing, board roll or RF channel phase. The measured 1.40m is radial range only, not measured X/Y/Z.

A minimal future live-angle correction is to use actual-position steering for all12 channels and preserve static power in a mapping mode, rather than merely swapping four indices. For a horizontal-only diagnostic, channels0..3 and8..11 form the nominal eight-element lower row. Elevation must account for both coordinates jointly; no guessed alternating sign correction is justified. Live acquisition files were left untouched because this request calls for a separately tested analysis correction.

4. Exactly where candidates are lost

The old CA-CFAR training radius is four range bins. On the selected negative beat branch, there are32 positive-distance cells, from0.04684 to1.49896m. Its code sets the first and last four cells false. The far exclusion starts at1.35843m and includes1.40528m, even though the requested interval is0.20–1.45m. Thus a target at1.40m is inside the requested gate but outside the detector's actual eligible cells. See eligibility per range bin.

The audited copy counts only available range training cells, recomputes the CA-CFAR multiplier for that count, and stops wrapping range neighbors from far to near. Doppler retains circular treatment. The default PFA0.001 and minimum SNR8dB are unchanged; they remain nominal statistics for windowed, channel-averaged power. Edge noise estimates have less support than interior estimates and are not promised to have calibrated false-alarm rates.

After CFAR, 3×3 range-Doppler local maxima remove neighboring repeats. The physical range gate then applies. Each surviving cell can branch into multiple local Bartlett peaks. A3dB relative window,20° separation and maximum3 angular peaks/cell are explicit selection stages. There is no overall XYZ cap by default. Per your instruction, low-coherence and search-boundary candidates are retained with flags, not discarded or relabeled as accurate. No static suppression was enabled for these outputs.

The per-frame counters and new stage tables separate RD cells from angular candidates. Those are different units: going from one RD cell to several angular candidates is expected, not newly measured surfaces.

The live DspConfig values (RTI floor3000, capture threshold3000, minimum14 threshold crossings, two required frames and eight-frame capture delay) affect feature displays or event-triggered feature saving. They do not select offline XYZ and do not alter the raw samples submitted beforehand. The only SNR-like live angle value is a log-summed amplitude scalar minus14.7, followed by display normalization; it is not the offline local CFAR SNR.

6. Confirmed observations versus unresolved causes

  • Confirmed: all395 decoded frames matched RadarStream's source decoder; calling the actual DataProcessor decoder also matched all76 frames of the1.40m test. This proves code agreement, not that the native capture library supplies the intended hardware order.
  • Confirmed: ADC sample55 has the highest mean power on all12 virtual channels in all five captures, including empty. Channel-specific peak/median power ratios range about33–396. This points to a repeatable fast-time pattern worth investigating; it does not by itself identify bad hardware, a packet header or a decoding fault. See channel audit. No samples were repaired.
  • Confirmed: each approximately10-second sidecar contains76–81 frames versus roughly250 predicted by supplied40ms cadence. JSON agrees with each binary and reports zero writer-queue drops, but does not bind the RF profile or provide frame timestamps / UDP counters.
  • Potential capture loss mechanism: DataProcessor polls one alternating buffer-half bit and performs DSP synchronously. If it misses buffer transitions, frames cannot be recovered from the raw recorder's queue counters. This is a design risk, not proof of historical loss. Native buffer/DLL source is unavailable.
  • Measured on this host now: eight-frame built-in benchmark, excluding first warm-up frame, averaged 17.2ms for time-plus-angle features, below40ms. This short test does not support claiming slow DSP caused these historical missing frames. See benchmark details.
  • Confirmed policy mismatch: a synthetic stationary return loses effectively all pre-display power under the live default slow-time mean subtraction (retained fraction 5.4e-31). Heatmap normalization/clipping is a display feature and cannot be used as calibrated power or proof that stationary energy survived.
  • Unresolved: ADC spike cause, active RF profile provenance, actual mount roll, interchannel phase, physical angle/velocity signs, reflector identity and multipath. Distance agreement alone cannot settle these.

8. Reuse with CPSL_TI_Radar / Jetson

No new offline processing system is needed. Keep transport separate from DSP. CPSL currently documents raw ADC over DCA1000 and firmware-produced serial TLV point clouds as different streams. Choose which one you need: receiving a firmware cloud is not the same as making this host DSP produce a cloud.

Reuse load_profile/validate_recording for offline provenance, decode_frame only when its binary layout is confirmed, range_fft, doppler_fft, isk_positions, steering_grid, tdm_compensate, corrected ca_cfar, estimate_angles, xyz_from_angles and calibration helpers. Existing radar_dsp.range_processing.range_processing, utils.windowing and doppler_processing are reusable low-level alternatives if their axes, scaling and already-separated TX convention are explicitly matched. Do not copy the whole live feature preprocessing into a furniture-mapping node.

Convert CPSL's documented ADC tensor/channel order into the canonical [loop,sample,TX-major/RX-minor] layout at one adapter boundary; preserve hardware timestamps and loss counters where available. Do not decode an already complex ADC cube again. Publish candidate point fields and quality flags, with a documented sensor-to-ROS transform. If the ROS frame uses X forward/Y left/Z up, it differs from this analysis's X right/Y forward/Z up. Jetson throughput and live integration were not tested here.
