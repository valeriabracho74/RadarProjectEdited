3. Live DSP: corrected geometry, full sampling and modes

The default FrameMapper calls the same range_fft, doppler_fft, isk_positions, steering_grid, tdm_compensate, corrected ca_cfar, estimate_angles, xyz_from_angles and calibration loader as the offline analysis. TX slot separation is canonicalized using the selected CFG's TX order. Receiver labels are still an assumption to confirm physically.

Geometry/Bartlett heatmaps accumulate compensated all-Doppler covariance, so moving and stationary power can contribute. Optional Capon/MUSIC display spectra use actual physical-position steering without ULA forward/backward assumptions; Capon uses diagonal loading and MUSIC explicitly assumes one source. Detected-cell direction candidates keep the comparable joint Bartlett snapshot method. Original library helpers remain available.

Mapping is the default and retains zero-Doppler returns. Motion mode intentionally removes the slow-time mean and can apply a configured minimum absolute velocity. The GUI makes the mode visible; mode/display changes are blocked during raw recording, and histories reset at a DSP frame boundary. New metadata records the policy, actual selected CFG text/hash, sample rate and mounting/calibration settings.

All ADC samples are used. No live step2/3 decimation remains selectable, so no anti-alias workaround is needed. The former feature behavior is retained only in backup for comparison. Numerical feature values change, despite preserved tensor dimensions; old trained feature classifiers were not revalidated.

The synthetic plot demonstrates the sampling error using a known tone. The recorded-map comparison changes algorithms, units, sampling and static policy; it is not a measured angular-accuracy comparison. Physical range axes now use the selected profile. RTI/DTI remain clearly labeled index-based feature views.

4. Capture isolation and sustained test

The raw observer copies an observed frame and submits it to RawRecorder before a separate bounded DSP queue. A slow DSP worker may skip queued frames for the display; these skips are counted separately from raw writer drops. DSP errors do not block raw submission. Timestamp/sequence diagnostics travel with each observation.

The DLL was read-only inspected and exports only captureudp; the host interface receives only a half flag and sample buffer. Native polling remains necessary. A flag change during copying is detected as an unstable copy. Unobserved even flag transitions, native overwrites, native incomplete frames and UDP gaps cannot be reconstructed; these remain null/unknown. An optional sequence-aware adapter protocol is supported, not assumed to be implemented by the DLL or CPSL.

9. Coordinate conventions and Jetson reuse

Analysis axes are X right/Y forward/Z up. Explicit mounting uses Rz(yaw) Rx(pitch) Ry(roll), with roll about forwardY, pitch about lateralX, yaw about upZ. Defaults remain zero; no rotation/sign was fitted to expected results. ROS is (analysisY,−analysisX,analysisZ) after mounting. CSV includes both versions. Full measured calibration and held-out XYZ validation remain necessary.

The numerical boundary is complex [same-TX loop, ADC sample, canonical TX-major/RX-minor channel]. CPSL input is not assumed to have RadarStream packing. adapt_virtual_cube requires explicit axes plus12 physical channel labels; adapt_tdm_chirps requires an explicit complex chirp/RX/sample layout and TX/RX permutations. Do not run the int16 decoder on a complex ADC cube. Bind sample rate, slope, ADC/ramp/idle timing, carrier, loops, frame period and timestamp provenance from the actual transport/profile.

Reuse FrameMapper and its existing audited numerical functions, with acquisition separate. Publish quality fields and real timestamp provenance with PointCloud2; do not confuse proximity-link IDs with object identities or registered surfaces. The added get_next_frame protocol is an adapter contract, not a tested CPSL API. No Jetson driver was installed or hardware integration attempted. CPSL's primary README distinguishes raw ADC transport from firmware-produced TLV point clouds.

10. Remaining experiments and physical limits

  1. With unchanged, known RF settings, record a new fixed scene and compare host timestamps/counters to configured25Hz. If short, use an independent sequence-aware capture to localize native/UDP loss. Do not infer loss solely from expected-versus-written totals.
  2. Use an isolated compact reflector at measured center, left/right and above/below XYZ. Check physical RX/TX labels, phase sign and mounting first; then estimate calibration and test it on separate held-out positions.
  3. Compare identical RF settings using an independent raw capture implementation. Determine whether the sample35/55 pattern follows source/capture, timing or hardware; preserve original data throughout.
  4. Measure true sensor-to-RViz latency and queue behavior on actual Jetson hardware. This Windows replay cannot establish it.

Finite waveform bandwidth, antenna aperture, specular surfaces, overlapping reflectors and multipath cannot be repaired by exporting extra dots. ISK has different horizontal and vertical aperture, so a sparse cloud need not outline the whole bin/box. The supplied waveform's signed half-band is about1.50m; farther returns can alias, and code cannot recover missing bandwidth or unobserved frames. No physical mapping accuracy or recognizable-surface claim is made.
